## 키워드 인자화(Transform Keyword Argument)

`키워드 인자화(Transform Keyword Argument)`는 매개변수를 `키워드 인자(Keyword Argument)`로만 전달받도록 강제하는 방법입니다.

이렇게 정의된 매개변수를 `키워드 전용 매개변수(Keyword-Only Parameter)`라 부릅니다.

`**kwargs`처럼 매개변수의 이름을 명확히 할당해야 함수를 사용할 수 있습니다.

<br>

[제 32강][32강]에서 다룬 것처럼, 일반 매개변수는 `func(1, 2)`처럼 위치로도, `func(a=1, b=2)`처럼 키워드로도 값을 받을 수 있습니다.

어떤 방식으로 호출할지는 **함수를 사용하는 쪽**이 선택합니다. 그러므로, 함수를 만든 사람이 "이 값은 이름을 붙여서 전달해야 이해하기 쉽다"고 생각하더라도 위치로 전달하는 것을 막을 수 없습니다.

키워드 전용 매개변수는 함수를 **만드는 쪽**이 호출 방식을 정하는 기능입니다. 이름을 붙이지 않고 값을 전달하면 `TypeError`가 발생합니다.

<br>

이번 강좌에서는 키워드 전용 매개변수가 왜 필요한지 먼저 살펴본 다음, 정의하는 방법과 기본값, 자주 발생하는 오류, 표준 라이브러리에서 실제로 사용되는 예, 그리고 위치 전용 매개변수와 함께 사용하는 방법을 다룹니다.

<br>
<br>

## 키워드 전용 매개변수가 필요한 이유

{% highlight Python %}

def transfer(sender, receiver, amount, fee):
    print(f"{sender} → {receiver} : {amount}원 (수수료 {fee}원)")


transfer("박XX", "김XX", 10000, 500)
transfer("박XX", "김XX", 500, 10000)

{% endhighlight %}

**결과**
:    
박XX → 김XX : 10000원 (수수료 500원)<br>
박XX → 김XX : 500원 (수수료 10000원)<br>
<br>

위 함수는 보내는 사람, 받는 사람, 금액, 수수료를 위치 인자로 받습니다.

두 번째 호출은 금액과 수수료의 **순서를 바꿔 전달하는 실수**를 한 것입니다. 두 값 모두 정수이므로 Python은 이 실수를 알아챌 수 없고, 500원을 보내면서 수수료로 10000원을 내는 잘못된 결과가 **오류 없이** 실행됩니다.

또한, `transfer("박XX", "김XX", 10000, 500)`이라는 호출만 보고 `10000`과 `500` 중 어느 쪽이 금액인지 알려면 함수의 정의를 찾아봐야 합니다.

<br>

이처럼 위치 인자는 다음과 같은 문제가 있습니다.

첫째, **호출하는 코드만으로는 값의 의미를 알기 어렵습니다.** 특히 `True`, `False`나 숫자처럼 그 자체로는 의미가 드러나지 않는 값일수록 더 그렇습니다.

둘째, **자료형이 같은 인자의 순서를 바꿔도 오류가 발생하지 않습니다.** 잘못된 결과가 그대로 사용되어, 나중에 엉뚱한 곳에서 문제가 드러납니다.

셋째, 함수를 수정해 **매개변수의 순서를 바꾸거나 중간에 추가**하면, 기존 호출 코드가 오류 없이 다른 의미로 동작하게 됩니다. 이는 아래에서 다시 다룹니다.

<br>

{% highlight Python %}

def transfer(sender, receiver, *, amount, fee):
    print(f"{sender} → {receiver} : {amount}원 (수수료 {fee}원)")


transfer("박XX", "김XX", amount=10000, fee=500)
transfer("박XX", "김XX", fee=500, amount=10000)

try:
    transfer("박XX", "김XX", 500, 10000)
except TypeError as e:
    print("TypeError:", e)

{% endhighlight %}

**결과**
:    
박XX → 김XX : 10000원 (수수료 500원)<br>
박XX → 김XX : 10000원 (수수료 500원)<br>
TypeError: transfer() takes 2 positional arguments but 4 were given<br>
<br>

`amount`와 `fee`를 키워드 전용 매개변수로 바꾸면, 호출하는 코드에 `amount=10000, fee=500`처럼 **값의 의미가 함께 적힙니다.**

두 번째 호출처럼 순서를 바꿔 작성해도 이름으로 할당되므로 **결과가 같습니다.** 순서를 외울 필요가 없으므로 순서 실수가 생기지 않습니다.

이름 없이 위치로 전달하면 `TypeError`가 발생하므로, 앞의 예제처럼 잘못된 값이 조용히 사용되는 일을 막을 수 있습니다.

<br>
<br>

## Keyword Argument (1)

{% highlight Python %}

def func(name, *, value1, value2):
    total = value1 + value2
    print(name + "는", total, "입니다.")


func("Plus", value1=2, value2=3)

{% endhighlight %}

**결과**
:    
Plus는 5 입니다.<br>
<br>

매개변수를 선언할 때 이름 없는 `애스터리스크(Asterisk, *)`를 중간에 작성하면, 그 뒤의 매개변수들은 **키워드 전용 매개변수**가 됩니다.

함수의 `value1`과 `value2`는 함수를 사용할 때, 명시적으로 할당되어야 합니다.

인자의 사용 유/무를 강제하는 것이 아닌, 인자를 전달할 때 **키워드**로 전달하도록 강제합니다.

만약, 기본값이 할당되어 있다면 필수로 할당하지 않아도 됩니다.

또한, 인자를 전달할 때 `위치 인자(Positional Argument)`를 사용하듯이 순서를 지키지 않아도 됩니다.

<br>

이름 없는 `*`는 `*args`와 같은 위치에 작성하지만, **값을 받지 않는 구분자**입니다.

`*args`는 남은 위치 인자를 튜플로 모으지만, 이름 없는 `*`는 위치 인자를 더 이상 받지 않겠다는 표시입니다. 그러므로, `name` 이후에 위치 인자를 더 전달하면 오류가 발생합니다.

`*` 앞의 `name`은 일반 매개변수이므로 위치로도 키워드로도 전달할 수 있습니다. 예제에서는 `"Plus"`를 위치 인자로 전달했습니다.

위의 사항을 다음과 같이 사용할 수 있습니다.

<br>
<br>

## Keyword Argument (2)

{% highlight Python %}

def func(name, *, value1, value2=3, value3):
    total = value1 + value2 + value3
    print(name + "는", total, "입니다.")


func("Plus", value3=2, value1=3)

{% endhighlight %}

**결과**
:    
Plus는 8 입니다.<br>
<br>

위와 같이 인자의 순서를 무시해도 됩니다.

**기본값**이 할당되어 있다면 필수적으로 값을 입력하지 않아도됩니다.

예제는 `value1`에 `3`, 생략한 `value2`에 기본값 `3`, `value3`에 `2`가 할당되어 `3 + 3 + 2 = 8`이 출력됩니다.

<br>

일반 매개변수는 기본값이 있는 매개변수 **뒤에** 기본값이 없는 매개변수를 둘 수 없습니다. `def func(a=1, b):`는 `SyntaxError`입니다.

하지만 키워드 전용 매개변수는 위치로 할당되지 않으므로 이 제약이 없습니다. 예제처럼 기본값이 있는 `value2` 뒤에 기본값이 없는 `value3`을 둘 수 있습니다.

그러므로, 매개변수를 **의미에 맞는 순서**로 자유롭게 배치할 수 있습니다.

<br>

{% highlight Python %}

def save(path, data, *, overwrite=False, encoding="utf-8"):
    print(path, data, overwrite, encoding)


save("a.txt", "Hello")
save("a.txt", "Hello", overwrite=True)

{% endhighlight %}

**결과**
:    
a.txt Hello False utf-8<br>
a.txt Hello True utf-8<br>
<br>

실제로 가장 많이 사용하는 형태는 **기본값이 있는 키워드 전용 매개변수**입니다.

반드시 필요한 값(`path`, `data`)은 위치 인자로 받고, 동작을 바꾸는 **옵션**(`overwrite`, `encoding`)은 기본값을 둔 키워드 전용 매개변수로 받습니다.

대부분의 호출은 첫 번째 줄처럼 필수 값만 전달하고, 옵션이 필요할 때만 `overwrite=True`처럼 이름을 붙여 전달합니다.

`save("a.txt", "Hello", True)`처럼 작성할 수 없으므로, 호출 코드에서 `True`가 무엇을 의미하는지 항상 알 수 있습니다.

<br>
<br>

## 키워드로 전달하지 않은 경우

{% highlight Python %}

def func(name, *, value1, value2):
    total = value1 + value2
    print(name + "는", total, "입니다.")


try:
    func("Plus", 2, 3)
except TypeError as e:
    print("TypeError:", e)

try:
    func("Plus", value1=2)
except TypeError as e:
    print("TypeError:", e)

{% endhighlight %}

**결과**
:    
TypeError: func() takes 1 positional argument but 3 were given<br>
TypeError: func() missing 1 required keyword-only argument: 'value2'<br>
<br>

키워드 전용 매개변수에 값을 **위치로 전달**하면, 받을 수 있는 위치 인자의 개수를 넘었다는 `TypeError`가 발생합니다.

`func`는 위치 인자를 `name` 하나만 받을 수 있는데 3개를 전달했으므로 `takes 1 positional argument but 3 were given`이 출력됩니다.

기본값이 없는 키워드 전용 매개변수를 생략하면, `missing 1 required keyword-only argument` 오류가 발생합니다.

오류 메시지에 `keyword-only`가 표시되므로, 이 매개변수는 이름을 붙여 전달해야 한다는 것을 알 수 있습니다.

키워드 인자화는 `True`, `False`나 숫자처럼 **의미를 알기 어려운 값**을 전달하는 매개변수에 유용합니다.

<br>

{% highlight Python %}

def func(*, value):
    print(value)


func(value=1)

try:
    func(1)
except TypeError as e:
    print("TypeError:", e)

{% endhighlight %}

**결과**
:    
1<br>
TypeError: func() takes 0 positional arguments but 1 was given<br>
<br>

`*`를 매개변수 목록의 맨 앞에 작성하면, **모든 매개변수**가 키워드 전용이 됩니다.

위치 인자를 하나도 받지 않으므로, `func(1)`은 `takes 0 positional arguments` 오류가 발생합니다.

<br>

{% highlight Python %}

def func(name, *):
    pass

{% endhighlight %}

**결과**
:    
SyntaxError: named arguments must follow bare *<br>
<br>

이름 없는 `*` 뒤에는 **반드시 하나 이상의 매개변수**가 있어야 합니다.

`*` 뒤에 아무 매개변수도 없으면 `*`를 작성할 이유가 없으므로 `SyntaxError`가 발생합니다.

<br>

{% highlight Python %}

def func(name, *, value1, value2):
    print(name, value1, value2)


options = {"value1": 2, "value2": 3}
func("Plus", **options)

{% endhighlight %}

**결과**
:    
Plus 2 3<br>
<br>

키워드 전용 매개변수에는 사전을 `**`로 풀어서 전달할 수도 있습니다.

`**options`는 `value1=2, value2=3`으로 풀리므로, **키워드로 전달한 것**과 같습니다. 설정값을 사전으로 관리하다가 함수에 한 번에 전달할 때 유용합니다.

<br>
<br>

## 표준 라이브러리의 키워드 전용 매개변수

Python의 내장 함수와 표준 라이브러리에도 키워드 전용 매개변수가 널리 사용됩니다.

특히 동작을 바꾸는 **옵션**에 해당하는 매개변수는 대부분 키워드 전용으로 정의되어 있습니다.

<br>

{% highlight Python %}

data = ["banana", "kiwi", "apple"]

print(sorted(data, key=len, reverse=True))

try:
    sorted(data, len, True)
except TypeError as e:
    print("TypeError:", e)

try:
    data.sort(len)
except TypeError as e:
    print("TypeError:", e)

{% endhighlight %}

**결과**
:    
['banana', 'apple', 'kiwi']<br>
TypeError: sorted expected 1 argument, got 3<br>
TypeError: sort() takes no positional arguments<br>
<br>

`sorted(data, key=len, reverse=True)`의 `key`와 `reverse`는 키워드 전용 매개변수이므로, 호출하는 코드만 보고도 "길이를 기준으로, 역순으로 정렬한다"는 의미를 알 수 있습니다.

`sorted(data, len, True)`처럼 위치로 전달하면 `sorted`는 위치 인자를 하나만 받으므로 `TypeError`가 발생합니다.

목록의 `sort` 메서드는 모든 매개변수가 키워드 전용이므로, 위치 인자를 하나도 받지 않습니다.

만약 위치로 전달할 수 있었다면, `sorted(data, True)`처럼 `reverse`를 의도하고 작성한 코드가 `key`에 `True`를 전달하는 실수가 생길 수 있습니다.

<br>

{% highlight Python %}

import inspect
import json

print(inspect.signature(sorted))
print(inspect.signature(json.dumps))
print(inspect.signature(print))

{% endhighlight %}

**결과**
:    
(iterable, /, *, key=None, reverse=False)<br>
(obj, *, skipkeys=False, ensure_ascii=True, check_circular=True, allow_nan=True, cls=None, indent=None, separators=None, default=None, sort_keys=False, \*\*kw)<br>
(\*args, sep=' ', end='\n', file=None, flush=False)<br>
<br>

`inspect.signature(함수)`는 함수의 **매개변수 구성(시그니처)**을 반환합니다. `help(함수)`로도 같은 내용을 확인할 수 있습니다.

`sorted`는 `iterable` 하나만 위치로 받고(`/`), 나머지 `key`와 `reverse`는 `*` 뒤에 있으므로 키워드 전용입니다.

`json.dumps`는 변환할 객체 `obj` 하나만 위치로 받고, `indent`, `sort_keys`, `ensure_ascii` 등 **9개의 옵션이 모두 키워드 전용**입니다. 옵션이 이렇게 많으면 위치로 전달할 때 순서를 기억하기 어렵기 때문입니다.

`print`는 `*args` 뒤에 `sep`, `end`, `file`, `flush`가 있으므로, 이 매개변수들은 `*` 없이도 키워드 전용이 됩니다. `print("A", "B", "-")`의 `"-"`는 구분자가 아니라 **출력할 값**으로 처리됩니다.

<br>

{% highlight Python %}

import json

print(json.dumps({"b": 1, "a": [1, 2]}, sort_keys=True, ensure_ascii=False))

{% endhighlight %}

**결과**
:    
{"a": [1, 2], "b": 1}<br>
<br>

`json.dumps(객체, sort_keys=True, ensure_ascii=False)`처럼 옵션의 이름이 호출 코드에 적혀 있으므로, `json` 모듈의 문서를 보지 않아도 "키를 정렬하고, ASCII가 아닌 문자를 그대로 출력한다"는 의도를 알 수 있습니다.

이 밖에도 `max(iterable, *, key, default)`의 `key`와 `default`, `zip(*iterables, strict=False)`의 `strict` 등이 키워드 전용 매개변수입니다.

<br>

{% highlight Python %}

from dataclasses import dataclass


@dataclass(kw_only=True)
class Point:
    x: int
    y: int


print(Point(x=1, y=2))

try:
    Point(1, 2)
except TypeError as e:
    print("TypeError:", e)

{% endhighlight %}

**결과**
:    
Point(x=1, y=2)<br>
TypeError: Point.\_\_init\_\_() takes 1 positional argument but 3 were given<br>
<br>

`dataclasses` 모듈의 `@dataclass(kw_only=True)`를 사용하면, 자동으로 생성되는 `__init__`의 모든 매개변수가 키워드 전용이 됩니다. (Python 3.10 이상)

속성이 많은 클래스에서 `Point(1, 2)`처럼 위치로 생성하면 어느 값이 어느 속성인지 알기 어려우므로, 키워드로만 생성하도록 강제할 때 사용합니다.

오류 메시지의 `takes 1 positional argument`는 `self` 하나만 위치 인자로 받는다는 의미입니다.

- Tip : 데이터 클래스는 [제 50강][50강]에서 자세히 다룹니다.

<br>
<br>

## 함수를 수정할 때의 안전성

키워드 전용 매개변수는 함수를 **나중에 수정할 때**도 도움이 됩니다.

여러 곳에서 사용하는 함수에 매개변수를 추가하거나 순서를 바꾸면, 위치 인자로 호출하던 기존 코드의 의미가 바뀔 수 있습니다.

<br>

{% highlight Python %}

# 1.0 버전
# def save(path, data, overwrite=False):

# 2.0 버전 : encoding 매개변수를 중간에 추가
def save(path, data, encoding="utf-8", overwrite=False):
    print(path, data, encoding, overwrite)


save("a.txt", "Hello", True)

{% endhighlight %}

**결과**
:    
a.txt Hello True False<br>
<br>

1.0 버전에서 `save("a.txt", "Hello", True)`는 "덮어쓰기"를 의미하는 호출이었습니다.

2.0 버전에서 `encoding` 매개변수를 `overwrite` 앞에 추가하자, 같은 호출의 `True`가 `encoding`에 할당되었습니다.

결과처럼 `overwrite`는 `False`가 되고 `encoding`은 `True`가 되지만, **오류는 발생하지 않습니다.** 기존 코드를 하나도 고치지 않았는데 동작이 바뀐 것입니다.

<br>

옵션을 처음부터 `def save(path, data, *, overwrite=False)`처럼 키워드 전용으로 정의했다면, 호출 코드는 반드시 `overwrite=True`로 작성되어 있습니다.

이 경우 `encoding`을 어느 위치에 추가하든, 키워드 전용 매개변수의 순서를 바꾸든 **기존 호출 코드는 그대로 같은 의미로 동작**합니다.

그러므로, 다른 사람이 사용하는 함수나 라이브러리를 만들 때는 옵션 매개변수를 키워드 전용으로 정의해 두는 것이 좋습니다.

<br>
<br>

## 위치 전용 매개변수와 함께 사용

{% highlight Python %}

def func(name, /, value1, *, value2):
    total = value1 + value2
    print(name + "는", total, "입니다.")


func("Plus", 2, value2=3)
func("Plus", value1=2, value2=3)

{% endhighlight %}

**결과**
:    
Plus는 5 입니다.<br>
Plus는 5 입니다.<br>
<br>

`Python 3.8` 이상에서는 `슬래시(/)`로 `위치 전용 매개변수(Positional-Only Parameter)`도 정의할 수 있습니다.

`/` 앞의 `name`은 **위치로만**, `/`와 `*` 사이의 `value1`은 **위치나 키워드**로, `*` 뒤의 `value2`는 **키워드로만** 전달할 수 있습니다.

결과처럼 `value1`은 위치(`2`)로 전달해도, 키워드(`value1=2`)로 전달해도 같은 결과가 됩니다.

<br>

{% highlight Python %}

def func(name, *args, value):
    print(name, args, value)


func("Plus", 1, 2, value=3)

{% endhighlight %}

**결과**
:    
Plus (1, 2) 3<br>
<br>

`*args`를 사용하는 경우, `*args` 자체가 구분자 역할을 하므로 `*args` 뒤의 매개변수는 별도의 `*` 없이도 키워드 전용 매개변수가 됩니다.

`*args`가 남은 위치 인자 `1, 2`를 모두 가져가므로, `value`에는 키워드로만 값을 전달할 수 있습니다.

<br>

{% highlight Python %}

import inspect


def func(a, b=2, /, c=3, *args, d, e=5, **kwargs):
    pass


for name, param in inspect.signature(func).parameters.items():
    print(name, param.kind.name)

{% endhighlight %}

**결과**
:    
a POSITIONAL_ONLY<br>
b POSITIONAL_ONLY<br>
c POSITIONAL_OR_KEYWORD<br>
args VAR_POSITIONAL<br>
d KEYWORD_ONLY<br>
e KEYWORD_ONLY<br>
kwargs VAR_KEYWORD<br>
<br>

`inspect.signature(함수).parameters`로 각 매개변수가 **어떤 방식으로 값을 받는지** 확인할 수 있습니다.

`/` 앞의 `a`, `b`는 `POSITIONAL_ONLY`(위치 전용), `c`는 `POSITIONAL_OR_KEYWORD`(위치 또는 키워드), `*args` 뒤의 `d`, `e`는 `KEYWORD_ONLY`(키워드 전용)입니다.

`*args`와 `**kwargs`는 각각 `VAR_POSITIONAL`, `VAR_KEYWORD`로 표시됩니다.

- Tip : 위치 전용 매개변수에 대한 자세한 설명은 [제 32강][32강]에서 확인할 수 있습니다.

<br>
<br>

## 정리

| 형태 | 설명 | 특징 |
|:----:|:----:|:----:|
| `def func(a, *, b)` | `*` 뒤의 `b`는 키워드 전용 | `func(1, b=2)`로만 호출 |
| `def func(*, a, b)` | 모든 매개변수가 키워드 전용 | 위치 인자를 받지 않음 |
| `def func(*args, b)` | `*args` 뒤의 `b`는 키워드 전용 | `*` 없이도 키워드 전용 |
| `def func(a, /, b, *, c)` | 위치 전용, 일반, 키워드 전용 혼합 | 위치 전용은 3.8 이상 |
| 기본값 | `*, b=1, c` | 키워드 전용은 기본값 순서 제약 없음 |
| 위치로 전달 시 | `takes N positional arguments` | `TypeError` |
| 생략 시 | `missing required keyword-only argument` | `TypeError` |
| `@dataclass(kw_only=True)` | 생성자를 키워드 전용으로 | 3.10 이상 |

<br>

키워드 전용 매개변수는 **호출하는 코드에 값의 의미가 드러나게** 하고, 자료형이 같은 인자의 **순서 실수를 오류로 바꿔 줍니다.**

또한, 함수에 매개변수를 추가하거나 순서를 바꿔도 기존 호출 코드의 의미가 바뀌지 않으므로, 오래 유지하는 함수일수록 안전합니다.

`sorted`의 `key`, `reverse`나 `json.dumps`의 옵션처럼, 필수 값은 위치로 받고 **동작을 바꾸는 옵션은 키워드 전용**으로 정의하는 것이 일반적인 설계 방식입니다.
