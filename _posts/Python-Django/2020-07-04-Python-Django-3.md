## Django settings.py 설정

장고(Django)의 환경 설정은 `settings.py` 파일에서 관리할 수 있습니다.

환경 설정에서 `데이터베이스`, `디버그 모드`, `허용 가능한 호스트`, `애플리케이션`, `다국어 및 지역 시간` 등을 설정할 수 있습니다.

`settings.py` 파일의 설정이 올바르지 않거나, 필요한 구성이 누락되었다면 정상적으로 실행되지 않습니다.

## 기본 디렉토리 경로

{% highlight Python %}

BASE_DIR = Path(__file__).resolve().parent.parent

{% endhighlight %}

기본 디렉토리 경로는 `BASE_DIR`로 나타냅니다.

`settings.py` 파일의 상위 폴더의 상위 폴더, 즉 `manage.py`가 위치한 프로젝트 최상위 경로를 의미합니다.

`BASE_DIR`은 `pathlib.Path` 객체이므로, `BASE_DIR / 'templates'`처럼 슬래시(/) 연산자로 하위 경로를 만들 수 있습니다.

`BASE_DIR`은 임의적으로 디렉토리 구조를 수정한 경우가 아니라면 수정하지 않습니다.

- Tip : 예전 버전의 장고는 `os.path.join(BASE_DIR, 'templates')`처럼 `os.path` 모듈을 사용했습니다. 현재 버전은 `pathlib`을 사용합니다.

## 비밀 키

{% highlight Python %}

SECRET_KEY = '비밀 키'

{% endhighlight %}

`SECRET_KEY`는 프로젝트를 생성할 때 **무작위의 50 글자**로 만들어지며, `암호화 서명(Cryptographic signing)`, `세션 데이터`, `비밀번호 초기화 토큰`, `CSRF 토큰` 등에 사용됩니다.

`SECRET_KEY`는 노출되어서는 안되며, `SECRET_KEY` 키가 노출되었을 때는 **보안 기능이 상실**되므로, 새로운 `SECRET_KEY`를 사용해야 합니다.

`startproject`로 생성된 키는 `django-insecure-`로 시작하며, 개발용으로만 사용해야 한다는 의미입니다.

`SECRET_KEY`의 값은 코드와 분리해서 사용하며, 크게 `환경 변수에 등록`하거나 `비밀 파일로 저장`해 사용합니다.

<br>

### 비밀 키 분리 방법 (1)

{% highlight Python %}

import os

SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]

{% endhighlight %}

환경 변수에 비밀 키를 등록해서 사용할 수 있습니다.

`Windows`의 경우에는 명령 프롬프트의 `set`이나 PowerShell의 `$env:DJANGO_SECRET_KEY="..."`로, `Mac`이나 `Linux`는 터미널의 `export` 명령어로 등록할 수 있습니다.

영구적으로 등록하려면 `.bashrc`, `.zshrc`, `.profile` 등에 등록합니다.

<br>

### 비밀 키 분리 방법 (2)

{% highlight Python %}

from keyfile import secret_key

SECRET_KEY = secret_key

{% endhighlight %}

간단하게 `*.py` 파일을 생성한 다음, 변수로 등록해 사용하거나, `json` 파일에 `SECRET_KEY` 값을 저장한 다음 불러와 사용할 수 있습니다.

이때, `git`과 같은 버전관리 시스템을 사용한다면, `.gitignore`에 해당 파일을 추가해 저장되지 않도록 합니다.

<br>

### 새로운 비밀 키 생성

{% highlight Python %}

from django.core.management.utils import get_random_secret_key

print(get_random_secret_key())

{% endhighlight %}

비밀 키가 노출되었거나 운영 환경용 키가 필요하다면, `get_random_secret_key()` 함수로 새로운 비밀 키를 생성할 수 있습니다.

## 디버그 모드

{% highlight Python %}

DEBUG = True

{% endhighlight %}

디버그 모드는 프로그램을 개발할 때 사용되는 모드입니다.

`True`로 설정되어 있다면, 오류가 발생했을 때 **추적 정보(Traceback)**, **설정값**, **요청 정보** 등이 포함된 상세한 오류 페이지를 표시합니다.

상세한 오류 페이지에는 내부 정보가 노출될 수 있습니다.

개발이 완료되고 `운영` 서버 등에 배포할 때는 필히 디버그 모드를 `False`로 사용해야 합니다.

- Tip : `DEBUG = False`일 때는 `runserver`가 정적 파일(CSS, JavaScript 등)을 제공하지 않으므로, 웹 서버나 `whitenoise` 같은 패키지로 정적 파일을 제공해야 합니다.

- Tip : `python manage.py check --deploy` 명령어로 운영 환경 배포 전에 보안 설정을 점검할 수 있습니다.

<br>
<br>

## 허용 가능한 호스트

{% highlight Python %}

ALLOWED_HOSTS = []

{% endhighlight %}

허용 가능한 호스트는 운영 서버 등에 배포하여, 서비스할 때 **호스트로 사용 가능한** `호스트` 또는 `도메인` 목록입니다.

요청의 `Host` 헤더가 목록에 등록되어 있지 않다면, `Bad Request (400)`를 반환합니다.

해당 기능은 `HTTP Host 헤더 공격`을 막기 위한 조치입니다.

`DEBUG = True`이고 `ALLOWED_HOSTS`가 비어 있다면, `localhost`, `127.0.0.1`, `[::1]`이 자동으로 허용됩니다.

`DEBUG = False`라면 서비스하는 도메인을 반드시 등록해야 정상적으로 동작합니다. 구성은 아래와 같이 사용할 수 있습니다.

{% highlight Python %}

ALLOWED_HOSTS = ['localhost', '127.0.0.1', '076923.github.io']

{% endhighlight %}

`DEBUG = False`인 상태에서 `ALLOWED_HOSTS`가 비어 있다면, `CommandError: You must set settings.ALLOWED_HOSTS if DEBUG is False.`의 오류를 반환하며 `manage.py runserver`가 작동하지 않습니다.

- Tip : `.076923.github.io`처럼 온점(.)으로 시작하면 해당 도메인과 모든 하위 도메인을 허용합니다.

- Tip : 모든 호스트를 허용한다면 `ALLOWED_HOSTS = ['*']`으로 설정합니다. 단, 운영 환경에서는 보안상 권장하지 않습니다.

## 설치된 애플리케이션

{% highlight Python %}

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
]

{% endhighlight %}

현재 장고 프로젝트에 설치된 애플리케이션의 목록을 의미합니다.

애플리케이션을 등록하지 않는다면 서비스에서 사용할 수 없습니다.

현재 프로젝트는 `REST Framework`와 `CORS` 패키지를 등록할 예정이므로 아래와 같이 추가합니다.

<br>

### 애플리케이션 등록

{% highlight Python %}

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'rest_framework',
    'corsheaders',
    # '앞으로 추가할 애플리케이션',
]

{% endhighlight %}

`rest_framework`와 `corsheaders`는 1강에서 설치한 `Django REST Framework`와 `Django CORS`입니다.

해당 애플리케이션을 등록하지 않는다면, 장고 프로젝트에서 위의 기능을 사용할 수 없습니다.

`앞으로 추가할 애플리케이션`은 `startapp` 명령어를 통해 생성된 `Python` 패키지를 의미합니다.

추가되는 애플리케이션은 모두 `INSTALLED_APPS` 목록에 추가해야합니다.

- Tip : `startapp` 명령어는 4강 `애플리케이션 생성`에서 확인할 수 있습니다.

<br>

### CORS 허용

{% highlight Python %}

CORS_ALLOW_ALL_ORIGINS = False
CORS_ALLOW_CREDENTIALS = False

CORS_ALLOWED_ORIGINS = [
    'http://localhost:3000',
    'https://076923.github.io',
]

{% endhighlight %}

`CORS` 패키지를 등록했다면, 위와 같은 내용을 추가합니다.

`CORS_ALLOW_ALL_ORIGINS`는 모든 출처(Origin)의 HTTP 요청을 허용합니다. 개발 중에만 `True`로 사용합니다.

서비스 중인 서버에서는 `False`로 사용하고, `CORS_ALLOWED_ORIGINS`에 허용할 출처를 등록합니다.

`CORS_ALLOWED_ORIGINS`는 사이트 간 요청을 허용하는 출처 목록입니다. 출처는 **프로토콜(http, https)을 포함**하고, 경로나 마지막 슬래시(/) 없이 작성해야 합니다.

`CORS_ALLOW_CREDENTIALS`는 쿠키나 인증 헤더를 사이트 간 HTTP 요청에 포함할 수 있는지 설정합니다.

- Tip : 예전 버전에서 사용하던 `CORS_ORIGIN_ALLOW_ALL`, `CORS_ORIGIN_WHITELIST`는 각각 `CORS_ALLOW_ALL_ORIGINS`, `CORS_ALLOWED_ORIGINS`로 이름이 변경되었습니다.

- Tip : `CORS_ALLOWED_ORIGIN_REGEXES`를 사용하면 정규표현식으로 출처를 허용할 수 있습니다.

<br>

{% highlight Python %}

from corsheaders.defaults import default_headers, default_methods

CORS_ALLOW_HEADERS = (
    *default_headers,
    'my-custom-header',
)

CORS_ALLOW_METHODS = (
    *default_methods,
)

{% endhighlight %}

`CORS_ALLOW_HEADERS`는 **예비 요청(preflight request)** 응답의 `Access-Control-Allow-Headers`에 사용되는 헤더 목록입니다.

`CORS_ALLOW_METHODS`는 **예비 요청** 응답의 `Access-Control-Allow-Methods`에 사용되는 **HTTP 메서드** 목록입니다.

기본값에는 `accept`, `authorization`, `content-type`, `user-agent`, `x-csrftoken`, `x-requested-with` 헤더와 `DELETE`, `GET`, `OPTIONS`, `PATCH`, `POST`, `PUT` 메서드가 포함되어 있습니다.

기본값으로 충분하다면 두 설정은 작성하지 않아도 되며, 사용자 정의 헤더가 필요한 경우에만 기본값에 추가해 사용합니다.

## 미들웨어

{% highlight Python %}

MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]

{% endhighlight %}

`미들웨어(middleware)`란 운영 체제와 응용 소프트웨어의 중간에서 **조정**과 **중개**의 역할을 수행하는 소프트웨어입니다.

장고의 미들웨어는 장고에서 발생하는 `요청(Request)`과 `응답(Response)` 처리 과정에 끼어들어 동작하는 **플러그인(Plugin)** 형태의 프레임워크입니다.

`보안 헤더 추가`, `세션`, `CSRF 검증`, `사용자 인증` 등이 미들웨어로 처리됩니다.

요청은 목록의 **위에서 아래** 순서로, 응답은 **아래에서 위** 순서로 미들웨어를 통과하므로, 등록 순서가 중요합니다.

<br>

### 미들웨어 등록

{% highlight Python %}

MIDDLEWARE = [
    'corsheaders.middleware.CorsMiddleware',
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]

{% endhighlight %}

`CORS` 미들웨어는 응답을 생성할 수 있는 다른 미들웨어보다 **가능한 한 위쪽**에 등록해야 합니다.

특히 `CommonMiddleware`보다 위에 있어야 하므로, 일반적으로 목록의 **가장 최상단**에 등록합니다.

추가적으로 등록되는 미들웨어는 역할에 맞는 위치에 등록합니다.

<br>
<br>

## 템플릿

{% highlight Python %}

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

{% endhighlight %}

장고는 웹 사이트에서 활용할 수 있으므로 `html` 코드 등과 연동하여 사용할 수 있습니다.

`BACKEND`는 사용할 템플릿 백엔드를 설정합니다. 아래와 같이 템플릿을 변경해 사용할 수 있습니다.

* 'BACKEND': 'django.template.backends.django.DjangoTemplates'
* 'BACKEND': 'django.template.backends.jinja2.Jinja2'

`DIRS`는 장고가 템플릿 소스 파일을 찾아야하는 디렉터리 경로 목록입니다.

`APP_DIRS`는 장고가 설치된 애플리케이션의 `templates` 폴더에서 템플릿 소스 파일을 찾는 여부입니다.

`OPTIONS`는 템플릿 백엔드에 전달할 추가 매개 변수입니다. 사용 가능한 매개 변수는 템플릿 백엔드에 따라 달라집니다.

<br>

### 템플릿 등록

{% highlight Python %}

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

{% endhighlight %}

템플릿을 사용하는 경우 `DIRS`에 템플릿이 저장된 경로를 등록합니다.

현재 프로젝트 경로의 `templates` 폴더에서 템플릿을 검색합니다.

만약, 템플릿을 사용하지 않는다면 등록하지 않아도 됩니다.

<br>
<br>

WSGI_APPLICATION = 'daehee.wsgi.application'

{% endhighlight %}

- Tip : 비동기 서버(ASGI)를 사용하는 경우에는 `asgi.py`의 `application` 객체를 서버에 직접 지정합니다. (예 : `uvicorn daehee.asgi:application`)

## 데이터베이스 설정

{% highlight Python %}

DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}

{% endhighlight %}

기본값으로 `SQLite`가 설정되어 있으며, 특정 데이터베이스를 연동할 때 `DATABASES` 설정값을 변경합니다.

`ENGINE`은 데이터베이스의 엔진을 의미하며, `MySQL`(`MariaDB`)이나 `PostgreSQL`, `Oracle` 등을 연동할 수 있습니다.

<br>

### MySQL 연동

{% highlight bash %}

pip install mysqlclient

{% endhighlight %}

`MySQL`을 연동하기 위해서는 `mysqlclient`를 설치합니다.

{% highlight Python %}

'ENGINE': 'django.db.backends.mysql'

{% endhighlight %}

설치가 완료된 후, `ENGINE` 값을 수정해 사용할 수 있습니다.

- Tip : `mysqlclient`는 Linux, macOS에서 MySQL 개발 헤더 등 빌드 도구가 필요할 수 있습니다. MariaDB도 같은 `ENGINE`을 사용합니다.

<br>

### PostgreSQL 연동

{% highlight bash %}

pip install "psycopg[binary]"

{% endhighlight %}

`PostgreSQL`을 연동하기 위해서는 `psycopg`(psycopg 3)를 설치합니다.

{% highlight Python %}

'ENGINE': 'django.db.backends.postgresql'

{% endhighlight %}

설치가 완료된 후, `ENGINE` 값을 수정해 사용할 수 있습니다.

- Tip : 예전 강좌에서 사용하던 `psycopg2`도 사용할 수 있지만, 장고 공식 문서는 새 프로젝트에 `psycopg`(3) 사용을 권장합니다.

<br>

### 데이터베이스 설정 수정

{% highlight Python %}

DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'HOST': os.environ['DB_HOST'],
        'PORT': os.environ['DB_PORT'],
        'NAME': os.environ['DB_NAME'],
        'USER': os.environ['DB_USER'],
        'PASSWORD': os.environ['DB_PASSWORD'],
    }
}

{% endhighlight %}

데이터베이스를 연동시, `호스트(HOST)`, `포트(PORT)`, `이름(NAME)`, `유저(USER)`, `비밀번호(PASSWORD)`를 설정해야합니다.

`호스트(HOST)`는 데이터베이스의 **주소**입니다. 만약, 로컬에서 사용하고 있다면, `localhost`를 입력합니다.

`포트(PORT)`는 데이터베이스의 **포트 번호**입니다. 데이터베이스에서 사용하고 있는 포트 번호를 작성합니다.

`이름(NAME)`은 연동할 **데이터베이스의 이름**을 의미합니다. 사용할 데이터베이스의 이름을 입력합니다.

`유저(USER)`는 데이터베이스에 접속할 **계정 이름**을 의미합니다.

`비밀번호(PASSWORD)`는 접속할 데이터베이스에 설정된 **비밀번호**를 의미합니다.

데이터베이스 설정은 `SECRET_KEY`와 같이 예제처럼 환경 변수 등으로 별도로 관리해야 합니다.

데이터베이스의 접속 정보가 노출된다면, **보안 기능이 상실**되므로 큰 위험을 초래하게 됩니다.

<br>

### 클라우드 데이터베이스 연동

{% highlight Python %}

DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'HOST': 'daehee.076923.ap-northeast-2.rds.amazonaws.com',
        'PORT': 5432,
        'NAME': os.environ['DB_NAME'],
        'USER': os.environ['DB_USER'],
        'PASSWORD': os.environ['DB_PASSWORD'],
    }
}

{% endhighlight %}

AWS RDS와 같이 클라우드 환경의 데이터베이스와 장고를 연동할 수 있습니다.

클라우드 데이터베이스의 `엔드포인트`를 **호스트(HOST)**에 문자열로 입력합니다.

클라우드 데이터베이스의 `포트`를 **포트(PORT)**에 입력합니다.

위의 예시와 같이 연동해 사용할 수 있습니다.

- Tip : 요청마다 연결을 새로 맺지 않도록 `'CONN_MAX_AGE': 60`처럼 연결 유지 시간(초)을 설정하거나, PostgreSQL에서는 `'OPTIONS': {'pool': True}`로 연결 풀(Connection Pool)을 사용할 수 있습니다.

<br>

## 비밀번호 유효성 검사

{% highlight Python %}

AUTH_PASSWORD_VALIDATORS = [
    {
        'NAME': 'django.contrib.auth.password_validation.UserAttributeSimilarityValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.MinimumLengthValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.CommonPasswordValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.NumericPasswordValidator',
    },
]

{% endhighlight %}

사용자 **비밀번호의 강도**를 확인하는 데 사용되는 `유효성 검증기 목록`입니다.

`UserAttributeSimilarityValidator`는 사용자의 **아이디**, **이름**, **이메일** 등의 속성이 **비밀번호**와 유사한지 확인합니다.

`MinimumLengthValidator`는 비밀번호의 최소 길이를 확인합니다. 기본값은 **8자**입니다.

`CommonPasswordValidator`는 비밀번호가 흔히 사용되는 비밀번호 목록에 포함되는지 확인합니다.

`NumericPasswordValidator`는 비밀번호가 숫자로만 구성되어있는지 확인합니다.

## 다국어 및 지역 시간 설정

{% highlight Python %}

LANGUAGE_CODE = 'en-us'

TIME_ZONE = 'UTC'

USE_I18N = True

USE_TZ = True

{% endhighlight %}

`LANGUAGE_CODE`는 장고 프로젝트에서 사용되는 기본 언어를 설정합니다.

`TIME_ZONE`은 프로젝트의 **기본 시간대**를 설정하는 문자열입니다.

`USE_I18N`은 장고의 **번역 시스템** 활성화 여부를 설정합니다.

`USE_TZ`는 장고가 **시간대를 인식하는(aware) 날짜/시간**을 사용할지 여부를 설정합니다.

`USE_TZ = True`라면 데이터베이스에는 **UTC**로 저장되고, 템플릿이나 폼에서 표시할 때 `TIME_ZONE`의 시간대로 변환됩니다.

- Tip : `I18N`은 `국제화(Internationalization)`의 약어입니다.

- Tip : 예전 버전에 있던 `USE_L10N` 설정은 Django 5.0에서 제거되었으며, 현재는 현지화된 형식이 항상 사용됩니다.

<br>

### 다국어 및 지역 시간 변경

{% highlight Python %}

LANGUAGE_CODE = 'ko-kr'

TIME_ZONE = 'Asia/Seoul'

USE_I18N = True

USE_TZ = True

{% endhighlight %}

다국어 및 지역시간을 한국 시간대에 맞춘다면, 위와 같이 변경해 사용합니다.

관리자 페이지 등 장고에 내장된 문구가 한국어로 표시됩니다.

- Tip : DRF의 응답은 `USE_TZ = True`일 때 `TIME_ZONE`에 맞춰 시간대 정보(예 : `+09:00`)가 포함된 형식으로 직렬화됩니다.

<br>
<br>

## 정적 파일 설정

{% highlight Python %}

STATIC_URL = 'static/'

{% endhighlight %}

`STATIC_URL`은 정적 파일을 참조할 때 사용할 URL을 의미합니다.

**CSS**, **JavaScript**, **이미지**와 같은 정적 파일 경로를 설정합니다.

비어 있지 않은 값으로 설정되면 슬래시(/)로 끝나야합니다.

- Tip : 사용자가 업로드한 파일은 정적 파일이 아닌 **미디어 파일**로 분류되며, `MEDIA_URL`과 `MEDIA_ROOT`로 별도 설정합니다.

<br>

### 정적 파일 경로 변경

{% highlight Python %}

STATICFILES_DIRS = [
    BASE_DIR / 'static',
]

STATIC_ROOT = BASE_DIR / 'staticfiles'

{% endhighlight %}

로컬 경로의 정적 파일을 사용한다면, 위와 같이 변경해 사용할 수 있습니다.

`STATICFILES_DIRS`는 앱의 `static` 폴더 외에 **추가로 정적 파일을 찾을 경로 목록**을 설정합니다.

`STATIC_ROOT`는 배포 시 `python manage.py collectstatic` 명령어로 **모든 정적 파일을 모아둘 경로**를 설정합니다.

- Tip : `STATIC_ROOT`와 `STATICFILES_DIRS`에 **같은 경로를 지정하면 안 됩니다.** 같은 경로를 사용하면 `The STATICFILES_DIRS setting should not contain the STATIC_ROOT setting.` 오류가 발생합니다.

<br>

## 기타 설정

`MAILERS`는 Django 6.1의 기본 프로젝트에 포함된 **이메일 발송** 설정입니다. 예전 버전의 `EMAIL_BACKEND` 설정을 대체합니다. 기본값은 이메일을 실제로 보내지 않고 콘솔에 출력하는 `console` 백엔드입니다.

이외에도 `DEFAULT_AUTO_FIELD`(기본 키 필드 타입), `LOGGING`(로그), `CACHES`(캐시), 서드파티 패키지의 설정(`REST_FRAMEWORK` 등)을 추가할 수 있습니다.

일반적으로 해당 강좌에 설명된 설정을 활용합니다.

만약, 데이터베이스를 사용하지 않고 `API` 등의 기능만 활용할 때에는 `DATABASES` 속성을 빈 사전(`{}`)으로 설정할 수 있습니다.

단, 이 경우 `admin`, `auth`, `sessions` 등 데이터베이스를 사용하는 기본 앱은 사용할 수 없습니다.

- Tip : 개발, 운영 환경별로 설정이 다르다면 `settings` 폴더를 만들어 `base.py`, `dev.py`, `prod.py`로 나누고, `DJANGO_SETTINGS_MODULE` 환경 변수로 사용할 설정을 선택할 수 있습니다.
